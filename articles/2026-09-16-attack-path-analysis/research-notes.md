# Research Notes: Attack Path Analysis

## Topic Summary
Attack path analysis (APA) is the cybersecurity practice of mapping how individual vulnerabilities, misconfigurations, and — increasingly — identity permissions chain together into exploitable routes from an attacker's entry point to a high-value asset. Where vulnerability scanning and attack surface management (ASM) answer "how exposed am I?" by listing isolated findings, attack path analysis answers "how dangerous is that exposure, given what it connects to?" by modeling the environment as a graph of relationships (users, groups, machines, permissions, sessions) and tracing the routes an attacker could actually traverse. Microsoft's own Security Exposure Management documentation frames it plainly: attack paths "combine assets and techniques to show end-to-end paths that attackers can create to get from an entry point of an organization to critical assets," and the same documentation introduces two operational concepts practitioners keep coming back to — a "choke point" (a node where multiple attack paths converge) and "blast radius" (how far a compromise cascades once a choke point falls).

The topic matters right now because identity keeps showing up as the dominant route in real incidents, while the sheer number of possible paths is exploding as non-human identities (service accounts, API keys, AI agents) proliferate. Palo Alto Networks' Unit 42 reported that identity weaknesses played a material role in nearly 90% of its 2026 Global Incident Response Report investigations. SpecterOps CTO Jared Atkinson has separately written that organizations with 10,000 identities face 22 million potential attack paths, describing that growth as exponential rather than linear. SpyCloud's September 2026 Identity Threat Report adds a fresh, dated data point on the same trend: compromised non-human identities are now the single most common primary breach entry point, ahead of phishing. Meanwhile Verizon's 2026 DBIR complicates a purely identity-centric narrative: vulnerability exploitation overtook stolen credentials as the single largest breach entry point for the first time in the report's 19-year history, a reminder that attack paths still need to account for unpatched software, not identity alone.

The discourse splits into three camps: (1) identity-security vendors treat attack path analysis as fundamentally an Active Directory/Entra ID/identity-graph problem (SpecterOps/BloodHound, Wikipedia's own "attack path management" entry); (2) cloud/CNAPP vendors treat it as a cloud misconfiguration + IAM graph problem (Wiz, Microsoft Defender for Cloud); (3) generalist ASM/exposure-management vendors treat it as one module bolted onto vulnerability data (Cymulate, CyCognito, Tenable, Rapid7, XM Cyber). For a company positioned in identity exposure management specifically, the identity-native framing is the most defensible and least commoditized angle, since most of the top-ranking generalist content treats identity as one input among many rather than the organizing principle of the analysis.

## Debates & Counterpoints
- **Is attack path analysis primarily an identity problem or an infrastructure/vulnerability problem?** Identity-security vendors and researchers (SpecterOps/Atkinson) argue attack paths are fundamentally about identity relationships (permissions, group memberships, sessions), citing incident-response data showing identity weaknesses are present in the vast majority of investigated breaches (Unit 42, 2026). But Verizon's 2026 DBIR complicates that: vulnerability exploitation (31%) overtook stolen credentials as the single largest entry point in 2026 — the first time in 19 years. The honest synthesis: initial access increasingly comes through unpatched software, but what happens after that first foothold (lateral movement, privilege escalation to a high-value asset) is overwhelmingly an identity-permissions problem — so attack path analysis needs both inputs, with identity as the connective tissue.
- **Is Gartner's CTEM breach-reduction prediction validated?** Vendor content widely cites a 2022 Gartner strategic-planning assumption that organizations prioritizing CTEM investment will be several times less likely to suffer a breach. This is a forecast, not a result from an independent study measuring CTEM adopters against non-adopters — no published data as of this research confirms or refutes that figure directly. Treat it as a prediction, not a proven outcome, when citing it.
- **Does attack path analysis actually reduce false positives/noise, or just relocate it?** Vendor glossary pages (XM Cyber, Tenable, CyCognito) claim large noise reductions via choke-point prioritization, but none of the top-ranking pages published independent, third-party-verified false-positive/false-negative rates for their own graph models — this is an evidence gap, not a resolved debate.
- **BloodHound: defensive tool or attacker enablement?** BloodHound is explicitly dual-use — the same open-source graph tool defenders use to find privilege-escalation paths in Active Directory/Entra ID is also used by real attackers and red teams. The security community's resolution is that this dual-use nature is precisely why defenders must run it (and monitor for its use) first, rather than avoid it.

## Content Gaps (Opportunities)
- No page in the top 10 walks through a single, concrete, end-to-end identity attack path (e.g., phishing → stale service-account credential → nested group membership → domain admin) with specific ATT&CK technique IDs at each hop — everyone stays at the generic "chain of vulnerabilities" abstraction level.
- No top-ranking page explains attack path analysis specifically for the audience choosing between an identity-native platform versus a generalist exposure-management add-on — i.e., "when is bolt-on attack-path visualization from your ASM/CNAPP tool not enough, and you need an identity-first graph instead?" This is squarely a wedge for a company positioned in preemptive identity exposure management (PIEM) covering both human and non-human identities.
- Non-human identity (NHI) attack paths are covered as a passing 2026 trend mention (SpyCloud, SpecterOps) but no educational "what is attack path analysis" page integrates NHI/machine-identity attack paths into its core methodology section as a first-class node type from the start.
- No page quantifies the "choke point" concept with a worked numeric example — the concept is explained qualitatively everywhere (including Microsoft Learn) but never made viscerally concrete with math, despite the SpecterOps 22-million-paths figure being publicly available to build that example from.
- The CTEM-to-attack-path connection is explained at a framework level but no page shows what "prioritization by attack path" looks like next to CVSS-only prioritization on the same example vulnerability set, and no page flags that the widely repeated Gartner CTEM breach-reduction figure is an unvalidated prediction rather than a measured outcome.
